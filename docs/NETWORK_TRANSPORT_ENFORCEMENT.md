# Network transport enforcement

Network decisions remain owned by `NetworkPolicy` and the runtime's `NetworkPolicyCenter`. `NetworkRequestAuthority` carries the initiating host context to a transport; it is not a second policy. A stale policy revision or source/account scope is refused rather than upgraded. Permission for an exact download batch does not authorize reader prefetch, another batch, or a verification page.

## Implemented admission boundaries

- Plugin HTTP checks its immutable context before each attempt, challenge retry and redirect. The download transport also invokes its existing admission gate at those boundaries and records its first refusal. Trust checks and destination cookie selection remain in the per-request delegate.
- Native plugin images retain the same authority through runner resolution and transfer. Default HTTP image loads use a per-request redirect delegate. Purpose marks are stripped only before wire transmission. Speculative image work checks the existing effective-preload projection before runner resolution. Cache hits remain local and need no network admission.
- The shared Nuke pipeline disables URL-only task coalescing, not caching. An unrelated foreground subscriber cannot promote a prefetch transfer. Each load owns cancellation and exactly-once completion: a cancelled load receives one `URLError(.cancelled)` completion and no data afterward. A visible reader replaces its own outstanding speculative task with a newly admitted visible task.
- Repository index/package requests and subtitles use the policy-aware HTTP adapter. Subtitle and playback admission retain the selected stream's source scope. Tracker SDK calls check admission at their app-owned request funnels; production sessions recheck redirects and strip credential headers when origins change. Existing per-entry write chains, fresh reads, account-session checks and acknowledgment rules remain in place. Automatic tracker sync publishes its acknowledged/deferred/unknown results; it has no new durable retry queue. A pre-admission policy refusal is not acknowledgment or bad credentials. A transport failure after a mutation begins is not proof of rollback and is not automatically replayed here.
- WebKit pages belong to a host operation. Website data is partitioned by source and authorization epoch in nonpersistent stores. A background/bulk operation is refused before constructing UI. Challenge instances own their page, continuation, deadline, cancellation and cleanup; cookie changes use WebKit's cookie-store observer rather than polling. One reader's cancellation does not settle another reader's challenge. Clear Site Data retires pages/challenges before acknowledging the clear. No request URL, script, cookie or response body is logged in these paths.
- AVPlayer checks before constructing and activating the remote asset. It uses the supported expensive/constrained network options and disables further use of a stream when its captured authority is revoked, best effort. It carries a typed refusal to presentation rather than returning nil for a policy denial.
- Native request/page deadlines map to the runner's `ItoError.hostCallTimedOut(.net/.webview)`, not synthetic HTTP 500 responses. This requires the parent integration's runner revision containing the additive `HostCallKind` API. Timeout is not a reason to retry an outcome-unknown mutation.

## Explicit exclusions and acceptance prerequisites

This is **not a strict Offline Only guarantee**. Revocation is best effort: bytes already in flight cannot be recalled.

1. `WKNavigationDelegate` governs navigations, not every WebKit HTTP subresource, service worker, JavaScript fetch, or internal retry. `WKWebsiteDataStore` isolation does not provide a universal HTTP interceptor. Validate login/challenge behavior, redirects, cancellation during postback, app-background transitions and Clear Site Data on the minimum supported iOS version and a current physical device. Source-scoped nonpersistent website stores intentionally do not promise cross-relaunch WebKit login persistence.
2. AVFoundation loads HLS playlists, segments, encryption keys and adaptive retries internally. A URLSession delegate does not intercept them. `AVAssetResourceLoaderDelegate` is not a universal interception hook for ordinary HTTP(S) assets. No proxy or URL-scheme rewrite is introduced. A physical-device matrix must observe HLS variant/segment/key redirects, live paused playback, Low Data Mode, cellular/expensive transitions, buffered playback and cancellation. Treat internal redirect-level enforcement as unsupported until demonstrated by a supported platform path.
3. Tracker SDKs currently expose concrete URLSession injection. Session delegates cover redirects, and app-owned funnels cover calls/retries initiated by Ito. Opaque retries inside an SDK are not verified pre-send gates, and a session-level redirect refusal can surface as a non-success response rather than the original typed refusal. Full attempt-level provenance would require an additive SDK transport/pre-send hook accepting the frozen authority (and preserving request cancellation and outcome-unknown writes). Do not claim universal tracker retry enforcement from the current session adapter.
4. Integrate the parent #167 lifecycle/capability fixes before compiling: `PluginNetworkContexts.scopeChanges`, operation-captured `scopedGrant`/`policyRevision`, `authorizeBatchOperation(_:operationID:)`, and exact `hasValidConsent(_:reference:operationID:authorizationScope:)`. Background entry and explicit grant revocation emit `NetworkPolicyCenter.changes` outside its lock. Transport subscriptions merge policy and scope invalidations. Integrate runner revision `9b0b2b50693db40fb23129e8cb1b02553d9e02ae` (or its successor with the timeout API). No plugin ABI/wire-layout change is needed.

## API evidence

The dependency pin is Nuke 12.9.0. Nuke's documented custom `DataLoading` seam accepts a URLRequest and cancellation handle; default coalescing is URL-based. Its `DataLoader` forwards session-level redirect callbacks, not a per-call authority closure. The custom default loader uses Foundation's real per-task `data(for:delegate:)` seam instead.

Apple documents `WKWebsiteDataStore.nonPersistent()`, `WKHTTPCookieStoreObserver`, `WKNavigationDelegate`, `AVURLAsset(url:options:)`, `AVPlayerItem.canUseNetworkResourcesForLiveStreamingWhilePaused` and `AVPlayer.replaceCurrentItem(with:)`. SDK headers declare both `AVURLAssetAllowsExpensiveNetworkAccessKey` and `AVURLAssetAllowsConstrainedNetworkAccessKey` available from iOS 13, below Ito's deployment target. None documents universal WebKit/HLS interception.
