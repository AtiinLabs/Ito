# Network transport enforcement

Network decisions remain owned by `NetworkPolicy` and the runtime's `NetworkPolicyCenter`. `NetworkRequestAuthority` carries the initiating host context to a transport; it is not a second policy. A stale policy revision or source/account scope is refused rather than upgraded. Permission for an exact download batch does not authorize reader prefetch, another batch, or a verification page.

## Implemented admission boundaries

- Plugin HTTP checks its immutable context before each attempt, challenge retry and redirect. The download transport also invokes its existing admission gate at those boundaries and records its first refusal. Trust checks and destination cookie selection remain in the per-request delegate.
- Native plugin images retain the same authority through runner resolution and transfer. Plain HTTP reader pages and source covers carry a host-only source authority property, supplied by the reader factory or prepared cover-request environment rather than inferred from a URL or header. Reader sessions (manga and novel) freeze their source epoch and operation when created and take the current policy revision each time a page request starts, so a settings change inside the reader never leaves the session refused; source rotation stops their queued/inflight work. Default HTTP image loads use a per-request redirect delegate. Both host properties are stripped before wire transmission, including direct `ito://` rewrites. Speculative image work checks the existing effective-preload projection before runner resolution. Cache hits remain local and need no network admission.
- The shared Nuke pipeline disables URL-only task coalescing, not caching. An unrelated foreground subscriber cannot promote a prefetch transfer. Each load owns cancellation and exactly-once completion: a cancelled load receives one `URLError(.cancelled)` completion and no data afterward. A visible reader that wants a page whose speculative transfer is already running joins that transfer: no second request is made and nothing is cancelled, but the transfer keeps the speculative authority it started with and only its Nuke priority rises. If that speculative transfer is refused or fails while the reader still waits, the reader gets exactly one fresh attempt under foreground authority derived from the same frozen source scope; that attempt's failure is terminal until Try Again. No fallback starts when the source scope has changed, or when the transfer ended because its last lease was released, the session was deactivated, or its requests were retained away. Speculative transfers run at low Nuke priority and visible ones at high; at most two speculative transfers run at once per reader session.
- Source-owned HTTP and `ito://` image caches are partitioned by source, authorization epoch and request headers/method/body while retaining Nuke's complete processor/thumbnail keys. A late old response cannot satisfy a new epoch or another source at the same URL. Source image memory is one bounded `ImageCache` whose keys are prefixed by that partition; its per-entry admission ratio is set to `1.0`, so entries with cost strictly below (not equal to) the existing total budget are eligible while the existing total-cost/count limits and LRU eviction remain in force. This avoids rejecting a large decoded image solely because it exceeds the default 10% per-entry threshold; it does not reserve residency for a reader lookahead window, so earlier prefetched pages can still be evicted when later images exceed the total budget. Clear Cache and any source/account scope change empty it, so an old account's decoded images are never served. Source transfers use their own session with no URLCache, no shared cookie storage and no credential storage, and the session is chosen by whether the authority is app-owned, not by a source label; Discover, tracker and repository images remain app-owned. After an epoch rotation the covers cached under the old epoch are orphaned and download again once. Wire URLs are not rewritten.
- Repository index/package requests and subtitles use the policy-aware HTTP adapter. Subtitle and playback admission retain the selected stream's source scope. Tracker SDK calls check admission at their app-owned request funnels; production sessions recheck redirects and strip credential headers when origins change. Existing per-entry write chains, fresh reads, account-session checks and acknowledgment rules remain in place. Automatic progress updates are logged but not surfaced or durably queued; policy deferral is not acknowledgment or bad credentials. A transport failure after a mutation begins is not proof of rollback and is not automatically replayed here.
- WebKit pages belong to a host operation. Website data is partitioned by source and authorization epoch in nonpersistent stores. A background/bulk operation is refused before constructing UI. A page or challenge the user already has open survives backgrounding and transient path loss (offline, unknown path); only a real revocation retires it (source/account scope change, a policy change that no longer admits it, Clear Site Data, explicit close). Requests made while backgrounded are refused one by one by the interactive check, and the same holds while a restore blocks the foreground. A Cloudflare challenge shows its page immediately; there is no silent auto-solve phase. Frames of a challenge page may load `about:`, `blob:` and `data:` documents, which are not requests; http(s) navigations need admission, and any other scheme is cancelled. Each plugin module keeps at most three idle web pages, evicting the least recently used; a page with a waiting load or script is never evicted. Challenge instances own their page, continuation, deadline, cancellation and cleanup; cookie changes use WebKit's cookie-store observer rather than polling. One reader's cancellation does not settle another reader's challenge. Clear Site Data raises a clearing barrier that spans the whole clear: pages and challenges that exist retire, and pages, challenges and website stores requested while the clear runs are refused, so nothing started during the clear survives it. Website contexts and the challenge manager are owned by the plugin manager's composition, not a global, and every other owner must be given that shared instance. No request URL, script, cookie or response body is logged in these paths.
- One user agent. No web view overrides its user agent, and every host web view (plugin pages, the Cloudflare challenge, the sign-in sheet) pins `preferredContentMode = .mobile`, so an iPad never switches to the desktop agent. `WebKitUserAgent`, owned by the plugin manager's composition and handed to every consumer, reads `navigator.userAgent` once from a web view configured the same way, warms when the runtime comes up, and backs off after a failed read instead of creating a web view per request; callers wait for it cancellably. Plugin HTTP, image transfers and downloads send that value in place of any `User-Agent` a plugin sets (under any header case); a Cloudflare clearance is resolved with it and fails as unavailable without it. When it cannot be read, a plugin's own header is sent unchanged.
- A plugin page stays on its site. After the plugin's own load commits, a main-frame navigation the page starts toward a different registrable domain is cancelled, so an advertisement cannot carry the page away; the plugin's own provisional load, including redirects to another domain, and subframes (embedded challenges) are not affected. The registrable domain comes from a small built-in suffix list, not the Public Suffix List; its limits are documented in `PluginPageNavigation`.
- AVPlayer checks before constructing and activating the remote asset. It uses the supported expensive/constrained network options and disables further use of a stream when its captured authority is revoked, best effort. It carries a typed refusal to presentation rather than returning nil for a policy denial. A transient path loss (offline or unknown path) never removes the item AVPlayer is playing or buffering; only a non-transient refusal (expensive or constrained path no longer allowed, a changed policy that disallows it, a source/account scope change) stops it.
- Native plugin request and page deadlines map to the runner's `ItoError.hostCallTimedOut(.net/.webview)`, not synthetic HTTP 500 responses. App-owned transports (repositories, subtitles, trackers) keep the system's `URLError`, so its localized text is shown. A late refusal replaces only the result of a read (GET, HEAD, OPTIONS) in both the plugin and app-owned transports; any other method keeps the remote's real answer. Deleting a plugin's cookies also invalidates its in-flight cookie writes. This requires the parent integration's runner revision containing the additive `HostCallKind` API. Timeout is not a reason to retry an outcome-unknown mutation.

## Explicit exclusions and acceptance prerequisites

This is **not a strict Offline Only guarantee**. Revocation is best effort: bytes already in flight cannot be recalled.

1. `WKNavigationDelegate` governs navigations, not every WebKit HTTP subresource, service worker, JavaScript fetch, or internal retry. `WKWebsiteDataStore` isolation does not provide a universal HTTP interceptor. Validate login/challenge behavior, redirects, cancellation during postback, app-background transitions and Clear Site Data on the minimum supported iOS version and a current physical device. Source-scoped nonpersistent website stores intentionally do not promise cross-relaunch WebKit login persistence.
2. AVFoundation loads HLS playlists, segments, encryption keys and adaptive retries internally. A URLSession delegate does not intercept them. `AVAssetResourceLoaderDelegate` is not a universal interception hook for ordinary HTTP(S) assets. No proxy or URL-scheme rewrite is introduced. A physical-device matrix must observe HLS variant/segment/key redirects, live paused playback, Low Data Mode, cellular/expensive transitions, buffered playback and cancellation. Treat internal redirect-level enforcement as unsupported until demonstrated by a supported platform path.
3. Direct-asset redirects performed by the chapter asset fetcher's URLSession are not rechecked against host policy; system network flags and cancellation are best effort only. Do not claim redirect-level enforcement for this path.
4. Headless webview use for metadata and prefetch is refused before a page is created; this includes work previously allowed to use a hidden page.
5. Tracker SDKs currently expose concrete URLSession injection. Session delegates cover redirects, and app-owned funnels cover calls/retries initiated by Ito. Opaque retries inside an SDK are not verified pre-send gates, and a session-level redirect refusal can surface as a non-success response rather than the original typed refusal. Full attempt-level provenance would require an additive SDK transport/pre-send hook accepting the frozen authority (and preserving request cancellation and outcome-unknown writes). Do not claim universal tracker retry enforcement from the current session adapter.
6. Dependencies this work relies on are integrated and pinned: `PluginNetworkContexts.scopeChanges`, operation-captured `scopedGrant`/`policyRevision`, `authorizeBatchOperation(_:operationID:)`, and exact `hasValidConsent(_:reference:operationID:authorizationScope:)`. Background entry and explicit grant revocation emit `NetworkPolicyCenter.changes` outside its lock. Transport subscriptions merge policy and scope invalidations. The runner is pinned at revision `9b0b2b50693db40fb23129e8cb1b02553d9e02ae`, which provides the typed timeout API. No plugin ABI/wire-layout change is needed.

## API evidence

The dependency pin is Nuke 12.9.0. Nuke's documented custom `DataLoading` seam accepts a URLRequest and cancellation handle; default coalescing is URL-based. Its `DataLoader` forwards session-level redirect callbacks, not a per-call authority closure. The custom default loader uses Foundation's real per-task `data(for:delegate:)` seam instead.

Apple documents `WKWebsiteDataStore.nonPersistent()`, `WKHTTPCookieStoreObserver`, `WKNavigationDelegate`, `AVURLAsset(url:options:)`, `AVPlayerItem.canUseNetworkResourcesForLiveStreamingWhilePaused` and `AVPlayer.replaceCurrentItem(with:)`. SDK headers declare both `AVURLAssetAllowsExpensiveNetworkAccessKey` and `AVURLAssetAllowsConstrainedNetworkAccessKey` available from iOS 13, below Ito's deployment target. None documents universal WebKit/HLS interception.
